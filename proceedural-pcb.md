# Procedural PCB — Rules for a FreeCAD Workbench

**Purpose:** extract the procedural rules SKiDL enforces so they can be ported into a FreeCAD workbench that builds PCBs from code — then identify what SKiDL *lacks* for real PCB design and spell out the improvements a 3D-native workbench must add.

**Audience:** developer porting this into a FreeCAD workbench (likely a mix of Python for logic + FreeCAD's `Part::Feature` / `Sketcher::SketchObject` for geometry).

**Status:** Extracted from `Comfac-Global-Group/skidl` @ 0de3738 (2026-04-20).

## Part 1 — The Rules SKiDL Already Has (Port These)

---

## 1. Procedural Primitives (the Nouns)

Five top-level objects. A procedural PCB workbench should mirror this model before adding PCB-specific primitives.

### 1.1 Part

Represents a component (resistor, IC, connector). Instantiated by looking up a symbol in a library:

```python
r = Part("Device", "R", value="10k", footprint="Resistor_SMD:R_0805_2012Metric")
```

| Attribute | Meaning |
|---|---|
| `name` | library symbol name ("R", "C", "Q_PNP_CBE") |
| `ref` | reference designator ("R1", "U3"); auto-assigned if blank |
| `value` | "10k", "100nF", "ATmega328P" |
| `footprint` | library:footprint string |
| `pins[]` | list of Pin |
| `circuit` | owning Circuit |
| `tag` | UUID linking to PCB instance |
| `hiername` | dot-path in hierarchy |
| `do_erc` | opt-out flag |

**Rule:** A Part always has pins. When constructed, it calls `associate_pins()` which sets `pin.part = self` for each pin.

### 1.2 Pin

The Part↔Net boundary.

| Attribute | Meaning |
|---|---|
| `num` | pin number (often a string: "1", "A3") |
| `name` | pin name ("VCC", "GPIO5", "~RESET") |
| `func` | pin type (14 enum values — §3) |
| `drive` | drive strength (8 enum levels) |
| `part` | back-ref to owning Part |
| `nets[]` | **list** of Nets — a pin may be on >1 net |
| `aliases[]` | alternative names |
| `do_erc` | opt-out flag |

### 1.3 Net

A named electrical wire (one equipotential).

| Attribute | Meaning |
|---|---|
| `name` | string (`"VCC"`); autogenerated `"N$7"` if unnamed |
| `_pins[]` | list of Pins on this net |
| `drive` | max drive currently applied |
| `netclasses[]` | list of NetClass metadata |
| `circuit` | owning Circuit |

### 1.4 Bus

An indexed collection of Nets — syntactic convenience for `DATA[0:7]`.

### 1.5 Circuit

Top-level container. Owns every Part, Net, Bus, and the root Node. Exactly one "active" Circuit at a time (module-global `default_circuit`).

**Special net:** every Circuit has an `NC` (no-connect) net; pins marked NOCONNECT attach here.

## 2. Connection Operators (the Verbs)

SKiDL's syntactic surface is small and almost entirely operator-based.

| Syntax | Meaning | Rule |
|---|---|---|
| `pin += net` | Add pin to net | Removes pin from NC net first; updates both pin.nets and net._pins |
| `net += pin, pin, …` | Add multiple pins | Same, in a loop |
| `net1 += net2` | Merge nets | `Net.join()` — drives max, netclasses unioned; cannot merge with NC |
| `pin1 += pin2` | Connect two pins | Route through a (possibly new) Net |
| `part[1] += net` | Pin-by-number | `Part.__getitem__` returns Pin, then `Pin.__iadd__` |
| `a & b & c` | **Series** | Connect in a chain — out of a to in of b, out of b to in of c |
| `a | b` | **Parallel** | Shared input and shared output |
| `2 * Part(...)` | Duplicate template | Returns N independent part instances |

**Invariant:** Pins never connect directly — always via a Net. `pin1 += pin2` either puts both on an existing net or creates a new one.

### 2.1 What a FreeCAD workbench inherits

Port all of this. Overloaded operators make procedural circuit description legible. FreeCAD Python can do exactly the same.

## 3. Pin Types (14 kinds, with semantics)

`pin.py` defines 14 pin types. Each has a nominal `drive`, a `min_rcv` (min drive required to function) and `max_rcv` (max drive tolerable).

| Pin type | drive | min_rcv | max_rcv | Plain-English semantics |
|---|---|---|---|---|
| INPUT | NONE | PASSIVE | POWER | Signal receiver; needs something driving it |
| OUTPUT | PUSHPULL | NONE | PASSIVE | Pushes signal; damaged if another OUTPUT fights |
| BIDIR | TRISTATE | NONE | POWER | Bidirectional I/O |
| TRISTATE | TRISTATE | NONE | TRISTATE | Can hi-Z; tolerates other tristates |
| PASSIVE | PASSIVE | NONE | POWER | Resistor, cap, inductor leg |
| PWRIN | NONE | POWER | POWER | Power-rail consumer (VCC pin on a chip) |
| PWROUT | POWER | NONE | PASSIVE | Power-rail source (regulator out) |
| OPENCOLL | ONESIDE | NONE | TRISTATE | Open-collector (needs pull-up) |
| OPENEMIT | ONESIDE | NONE | TRISTATE | Open-emitter |
| PULLUP | PULLUPDN | NONE | POWER | Pull-up resistor leg |
| PULLDN | PULLUPDN | NONE | POWER | Pull-down resistor leg |
| UNSPEC | NONE | NONE | POWER | Unspecified — ERC generates warnings |
| NOCONNECT | NOCONNECT | NOCONNECT | NOCONNECT | Intentional DNC — must stay on NC net |
| FREE | NONE | NOCONNECT | POWER | Unrestricted (special cases) |

### 3.1 Drive strength (ordered low to high)

```
NOCONNECT < NONE < PASSIVE < PULLUPDN < ONESIDE < TRISTATE < PUSHPULL < POWER
```

Used by ERC: a net's effective drive is `max(pin.drive for pin in net)`. Each pin checks its `min_rcv` against this — if the net's drive is lower than what a pin needs to function, ERC reports "insufficient drive."

## 4. ERC — The Full Rule Set

Electrical Rules Checking runs on every Part and every Net in the Circuit. Three layers of rules.

### 4.1 Part-level rules (`erc.py:dflt_part_erc`)

| Rule | Severity | Trigger |
|---|---|---|
| Unconnected pin | WARNING | Pin has no net and `func != NOCONNECT` |
| NOCONNECT wrongly connected | ERROR | Pin has `func == NOCONNECT` but is on a non-NC net |

### 4.2 Net-level rules (`erc.py:dflt_net_erc`)

| Rule | Severity | Trigger |
|---|---|---|
| No pins | WARNING | Net has zero pins attached |
| Only one pin | WARNING | Net is a dangling stub |
| Insufficient drive | ERROR | `max(pin.drive) < pin.min_rcv` for any pin |
| No drivers | ERROR | `max(pin.drive) <= NONE` (nothing actively drives the net) |
| Pin conflict | ERROR/WARNING | Any pin-pair hits the conflict matrix below |

## 5. Hierarchy Rules

- `@subcircuit`-decorated function pushes a new Node onto `active_node`, runs, pops.
- Parts created inside are attached to that Node; their `hiername` gains a segment.
- Hierarchy separator: `.` (`HIER_SEP` in `node.py`).
- **Nets are NOT scoped** — they live at Circuit level and cross hierarchy freely.
- When a net crosses a hierarchy boundary during schematic generation, a `NetTerminal` marker is inserted on each side.

### 5.1 What a FreeCAD workbench should add

- Keep SKiDL's flat-net model (nets span everything) — it's the electrical reality.
- But *also* track "logical containers" (subsheets / modules / rooms) for **placement constraints** — see §8.6.

## 6. Placement Rules (Force-Directed, 2D)

`schematics/place.py`. This is the placer SKiDL uses for schematic drawings — not for PCB, but the algorithm shape is reusable.

### 6.1 Phases

1. **Group formation.** Parts are split into (a) multiple groups of connected parts and (b) a single group of floating parts.
2. **BBox padding.** Every part's bbox is expanded to include routing channel space: padding per side = 1 + (number of pins on that side). `add_placement_bboxes()`, `place.py:123`.
3. **Orientation search.** For each part, test all 8 orientations (4 rotations × 2 mirror flips). Pick the one that minimises `net_tension` — the sum of squared distances from the part's anchor pins to its pull pins on other parts. `adjust_orientations()`, `place.py:265`.
4. **Force-directed relaxation.**
   - **Attractive force per net:** each net pulls its pins together, proportional to pin-to-centroid distance.
   - **Repulsive force per overlap:** bboxes that intersect push each other apart.
   - **Annealing:** attractive weight decreases over iterations; repulsive weight increases. Initially nets dominate (good topology); later overlaps dominate (no collisions).
5. **Overlap clearing.** Hard enforcement pass — remaining overlaps are shoved apart.
6. **Grid snap.** Snap final positions to the routing grid.

### 6.2 Anchor/pull pin model

For each net: the "anchor" pins are the pins on *this* part that touch the net; the "pull" pins are pins on *other* parts on the same net. Forces act between each anchor and each pull, not between whole parts. Centroid = mean position of anchor pins.

### 6.3 What a FreeCAD workbench should change for PCB

- Replace 2D bbox with **3D cuboid** (x, y, height). Height matters for:
  - Under-component clearance under connectors / stacked boards
  - Heat-dissipation spacing
  - Board-to-board collision in multi-board assemblies
- Replace orientation search (8 discrete states) with **rotation + mirror + side assignment** (top/bottom = 16 states for two-sided boards).
- Add **keepout / restricted zones** as hard placement constraints (§8.1).
- Add **placement rooms** (subcircuit → region mapping): placer prefers putting each subcircuit's parts inside its room.
- Net forces should respect **physical track length**, not just anchor-pull straight-line distance — once a rough place is done, pull from estimated Manhattan length.

## 7. Routing Rules (Schematic, 2D, Single-Layer)

`schematics/route.py` — 3200 lines. **Not PCB routing**, but the switchbox structure is relevant.

### 7.1 Phases

1. **Track extraction.** Horizontal and vertical tracks are drawn by extending every part edge outwards. These tracks partition space into rectangular **switchboxes**.
2. **Face construction.** Each switchbox is bounded by four Faces. Each Face carries a `capacity = length / grid_spacing`. Faces coinciding with a part edge have `capacity = 0` (nothing routes through a part).
3. **Global routing.** For each net, a maze router finds a sequence of Faces from source to destination. Moves only to adjacent switchboxes, only through Faces with remaining capacity.
4. **Terminal placement.** For each net's path, assign a coordinate on each Face where the wire crosses — the `Terminal` class (`route.py:142`). Parallel Face → pick nearest matching coord; perpendicular → pick nearest corner.
5. **Switchbox detail routing.** Within each switchbox, greedy single-layer router (Luk 1985) turns the Terminals into actual line segments.

### 7.2 Invariants enforced

- No routing inside parts (capacity = 0 on part-edge Faces).
- Orthogonal only (H and V segments, no diagonals).
- Multiple nets share a Face by using different coordinates along its length.
- Junctions emitted where a net's wire branches (3 or more pins connect).

### 7.3 Why this doesn't port to PCB as-is

SKiDL's router has:
- **One layer.** PCBs have 2, 4, 6, 8+ copper layers plus silk/mask.
- **No via model.** Layer crossings are free; on a PCB, a layer change costs a via.
- **No trace-width.** Schematic wires are infinitesimal; PCB traces have width, which eats channel capacity and must meet DRC.
- **No clearance rules.** Nets can share a coordinate in the schematic; on a PCB, nets must be separated by a clearance distance (dependent on voltage + netclass).
- **No impedance / differential-pair / length-match constraints.**
- **No copper pour / plane support.** Planes are not just wide traces — they need thermal reliefs at through-hole pins.

For a real PCB maker, treat SKiDL's router as inspiration only. Consider replacing with:
- **Per-layer A\*** (each layer is a grid graph; via cost for layer change)
- **Rip-up-and-retry** (route nets in priority order; on blocked nets, rip up lower-priority nets and try again)
- **Topological routing** (place terminals first, solve connection order via shortest-path, then expand to routes)

## 8. Netlist / Generation Rules

`tools/kicadN/gen_netlist.py`. The rules a FreeCAD workbench should follow when emitting board data.

### 8.1 Reference designator assignment

- Grouped by prefix: `R` for resistor, `C` for capacitor, `U` for IC, `Q` for transistor, `J` for connector, etc.
- Within a group, autoincrement from 1.
- Manually-set `ref` values are preserved and skipped during autoincrement.
- **Tie-break rule** (not in SKiDL but worth adding): assign by placement order (top-to-bottom, left-to-right) so that in the assembled board, R1 is always near the top-left.

### 8.2 Net naming

- Explicit `Net("VCC")` names are preserved.
- Unnamed nets get `N$1`, `N$2`, … from `get_unique_name()` (`net.py:114`).
- Multi-segment nets (joined via `join()`) merge under the alphabetically-first or highest-precedence name.

### 8.3 UUID / timestamp stability

Each Part gets a UUID5 hash of its `hiername`. This makes regeneration stable — a Part added to the same hierarchy path gets the same UUID across runs. A FreeCAD workbench should preserve this so that round-trips (edit the Python, re-run, diff the output) are clean.

## 9. Board Geometry — ADD

```python
board = Board(
    outline=Sketch.rect(80, 60),          # or any FreeCAD Sketch
    thickness=1.6,                         # mm
    mounting_holes=[(3,3), (77,3), (3,57), (77,57)],
    corner_radius=2,
)
```

Primitives to add:
- `Board(outline, thickness, ...)` — the substrate itself
- `Hole(position, drill, plating)` — through-hole, drilled, plated or not
- `Cutout(sketch)` — internal cut (for connectors, switches sticking through)
- `Keepout(sketch, layer, rule)` — no-copper / no-parts / no-via zones
- `EdgeConnector(sketch, pins)` — card-edge fingers

**FreeCAD mapping:** each of these is a `Part::Feature` built from a `Sketcher::SketchObject`. The board is `Pad` (extrude the outline).

## 10. Layer Stack — ADD

```python
board.stackup = Stackup([
    CopperLayer("F.Cu",   thickness=0.035, role="signal"),
    Dielectric("core1",   thickness=1.50),
    CopperLayer("B.Cu",   thickness=0.035, role="signal"),
])
```

For a 4-layer board:

```python
board.stackup = Stackup.standard_4_layer(
    signal_thickness=0.035,
    prepreg_thickness=0.2,
    core_thickness=1.065,
)
```

Layer metadata to track per layer:
- `role` — signal / plane / mixed
- `thickness` — mm
- `Dk` — dielectric constant (for impedance calc)
- `loss_tangent` — high-speed design
- `copper_weight` — oz or µm

Non-copper layers: `F.SilkS`, `B.SilkS`, `F.Mask`, `B.Mask`, `F.Paste`, `B.Paste`, `F.Fab`, `B.Fab`, `Edge.Cuts`, `User.Comments`.

## 11. Footprints — ADD (real, not just a string)

SKiDL treats footprint as an opaque string. A FreeCAD workbench should open the footprint and use it as geometry.

```python
fp = Footprint.load("Resistor_SMD:R_0805_2012Metric")
# fp.pads[]      — each with (position, shape, layers, drill)
# fp.outline     — courtyard polygon
# fp.height      — component height above board surface
# fp.model3d     — STEP/STL file reference
```

**Footprint-to-Part binding:** Pin number on the symbol must map to pad number on the footprint. SKiDL elides this check (deferred to pcbnew). A FreeCAD workbench should validate at bind time — raise if any symbol pin has no matching pad.

## 12. Design Rules (DRC) — ADD

Per-netclass rules, replacing SKiDL's netclass-as-metadata with netclass-as-constraint:

```python
power = NetClass("POWER",
    trace_width=0.5,           # mm
    clearance=0.3,
    via_diameter=0.8,
    via_drill=0.4,
)
signal = NetClass("SIGNAL",
    trace_width=0.2,
    clearance=0.15,
    via_diameter=0.5,
    via_drill=0.25,
)
high_speed = NetClass("HS",
    trace_width=0.15,
    clearance=0.2,
    impedance=50,              # ohms — forces substrate-aware width calc
    length_tolerance=1.0,      # mm — for length matching
    diff_pair_gap=0.15,
    diff_pair_via_gap=0.3,
)

vcc.netclass = power
mcu_xtal_a.netclass = signal
mcu_xtal_a.length_match_group = "xtal"
mcu_xtal_b.length_match_group = "xtal"
```

DRC checks every pair of tracks/pads for:
- Track-to-track clearance
- Track-to-pad clearance
- Pad-to-pad clearance
- Hole-to-hole spacing
- Silk-over-mask-opening
- Minimum annular ring
- Minimum drill size
- Minimum trace width

## 13. Vias, Planes, Pours — ADD

Via primitives:
- `Via(net, position, from_layer, to_layer, drill, size)` — through, blind, or buried depending on layers
- `MicroVia(...)` — for HDI

Copper pour:
- `Pour(net, layer, shape, clearance, thermal_relief)`
- Thermal reliefs: auto-inserted connecting pads on the pour net; width + gap from netclass
- Void-around-other-nets: enforced by DRC clearance

Plane layer helper:
- `board.plane(layer="In1.Cu", net=gnd, split=None)` — solid ground plane
- `board.plane(layer="In2.Cu", net=vcc, split={...})` — split plane with per-region net assignment

---

## 14. Side Assignment — ADD

Each Part gets a `side` attribute: `TOP` / `BOTTOM`. Controls which copper layer the footprint's pads land on. Placer should consider both sides. Rules:

- Through-hole parts: side = TOP (protrusion is BOTTOM but placement is TOP).
- SMD parts: either, subject to keepouts and assembly rules.
- Tall parts near board edges: may be forced to BOTTOM in some assemblies.

---

## 15. 3D Collision — ADD

Now that footprints carry height, and FreeCAD can attach 3D STEP models:

- **Component-to-component collision:** bbox intersection in 3D, not just 2D.
- **Component-to-enclosure collision:** project enclosure STEP into board space, check intersect.
- **Connector keep-out cones:** a connector's mating plug sweeps a volume; nothing may intrude.
- **Insertion-path collision:** for through-hole parts, the volume the part sweeps as it's inserted must not clash with existing SMDs on the opposite side.

FreeCAD's `Part::Common` (boolean intersect) is the primitive. A collision test is: is the intersection volume non-empty? Run once per placement iteration.

---

## 16. Length Matching & Impedance — ADD

High-speed rules SKiDL doesn't touch:

- **Length match groups:** all nets in the group end up within tolerance of the longest.
- **Serpentine insertion:** for short nets, router adds accordion-shaped meanders to reach target length.
- **Impedance-controlled widths:** given the netclass's target impedance and the stackup, compute trace width per layer (Hammerstad-Jensen or equivalent).
- **Differential pairs:** two nets routed together with fixed gap; DRC enforces pair-length skew budget.

---

## 17. Thermal & Mechanical — ADD

Not electrical, but essential:

- **Power dissipation per Part:** annotate `part.power = "1W"`; placer spreads heat sources.
- **Thermal-via arrays:** auto-generate on pads of power parts to link to plane.
- **Mounting-hole strain relief:** keep-out rings around screw holes (bending stress zone).
- **Flex sections:** designate a region as flex; DRC forbids through-holes and wide traces across the hinge.

## 18. Proposed FreeCAD Workbench API

Here's a sketch of what the final API could look like. Ported from SKiDL where possible, extended where SKiDL is silent.

```python
from ppcb import *

# === 1. Board substrate ===
board = Board(
    outline=Sketch.rect(80, 60, corner_radius=2),
    thickness=1.6,
    stackup=Stackup.standard_4_layer(),
    mounting_holes=[(3,3), (77,3), (3,57), (77,57)],
)

# === 2. NetClasses (DRC rules) ===
power  = NetClass("POWER",  trace_width=0.5, clearance=0.3, via=(0.8, 0.4))
signal = NetClass("SIGNAL", trace_width=0.2, clearance=0.15, via=(0.5, 0.25))

# === 3. Parts (same as SKiDL) ===
u1 = Part("MCU_Microchip", "ATmega328P-PU", footprint="Package_DIP:DIP-28_W7.62mm")
r1, r2 = 2 * Part("Device", "R", footprint="Resistor_SMD:R_0805_2012Metric")
r1.value, r2.value = "10k", "10k"

# === 4. Nets (same as SKiDL, plus netclass) ===
vcc = Net("VCC", netclass=power)
gnd = Net("GND", netclass=power)
rst = Net("~RESET", netclass=signal)

# === 5. Connections (same as SKiDL) ===
vcc += u1["VCC"], r1[1]
rst += u1["PC6"], r1[2]
gnd += u1["GND"], r2[2]

# === 6. Placement constraints ===
with Room("power_in", board, x=0, y=0, w=20, h=20):
    # parts inside this block are hinted to this region
    c_bulk = Part("Device", "CP", footprint="Capacitor_SMD:CP_Elec_8x10mm", value="470uF")
    gnd += c_bulk[2]; vcc += c_bulk[1]

u1.side = TOP
u1.position_hint = (40, 30)   # soft constraint — placer can override

# === 7. Ground plane ===
board.plane(layer="In1.Cu", net=gnd)
board.plane(layer="In2.Cu", net=vcc)

# === 8. Length matching example ===
xtal_a = Net("XTAL_A", netclass=signal, length_match_group="xtal")
xtal_b = Net("XTAL_B", netclass=signal, length_match_group="xtal")

# === 9. Checks ===
ERC()        # electrical rules — SKiDL's existing engine
DRC()        # design rules — new, checks trace width / clearance / etc.
Collision3D() # new — 3D interference check

# === 10. Execute ===
board.place()    # 3D-aware placer
board.route()    # layer-aware router with DRC
board.pour()     # copper pour on plane layers

# === 11. Output ===
board.export_step("board.step")         # 3D board with populated components
board.export_gerbers("gerbers/")         # manufacturing output
board.export_kicad_pcb("board.kicad_pcb") # for last-mile tweaks in pcbnew
board.export_bom("bom.csv")
board.export_cpl("pick_place.csv")
```

## 19. Implementation Plan (Phased)

### Phase 0 — Port the SKiDL core
Port `Part`, `Pin`, `Net`, `Bus`, `Circuit`, ERC, operator overloads. No FreeCAD integration yet — just ensure `ERC()` on a circuit behaves the same as upstream SKiDL.

### Phase 1 — Board geometry
Add `Board`, `Hole`, `Cutout`, `Keepout`. Emit a 3D substrate `Part::Feature` with holes cut. No copper yet.

### Phase 2 — Footprint binding
Load KiCad `.kicad_mod` footprints. Render pads on copper layers. Validate pin-to-pad mapping at bind time.

### Phase 3 — Placer
Force-directed placer adapted from `schematics/place.py`, but in 3D with side assignment, rooms, and hint support. Produce final positions that respect keepouts and mounting holes.

### Phase 4 — Router
Layer-aware A\* router with via cost, DRC-aware trace width and clearance. Start with 2-layer, extend to N. Skip length matching for MVP.

### Phase 5 — Pours
Copper pour generator with thermal reliefs. Split planes. DRC integration.

### Phase 6 — DRC
Full rule set: trace-to-trace clearance, pad clearance, annular ring, silk-over-mask, minimum drill/trace, NetClass enforcement.

### Phase 7 — Advanced
Length matching, impedance-controlled widths, differential pairs, 3D STEP export, enclosure-collision.

### Phase 8 — Ecosystem
Import/export to KiCad `.kicad_pcb` (round-trip), Gerber export, CPL/BOM, 3D STEP with component models from `ki_3dmodel` references.

## 20. Open Design Decisions

Things to decide before coding begins:

1. **Is the procedural model the source of truth, or a view onto FreeCAD document objects?**
   SKiDL is the former (Python dict of objects). FreeCAD typically expects the latter (everything is a `Document Object` with scripted recompute). Pick one; hybrid is painful.

2. **Netlist-first or geometry-first?**
   SKiDL is netlist-first (electrical graph → schematic → handed off for PCB). A FreeCAD workbench can be geometry-first (sketch board → drop footprints → draw copper → infer netlist). Decide which way the ground truth flows.

3. **Is the router interactive or batch?**
   SKiDL's is batch — generate schematic once. A PCB workbench could offer both: a "seed autoroute" pass + interactive push-and-shove after.

4. **Where does the netlist live during editing?**
   If the user hand-edits a trace in FreeCAD, does the procedural graph update? One option: FreeCAD stores the procedural model as a JSON blob inside the FCStd file and re-runs on change. Another: treat hand-edits as "overrides" stored separately.

5. **3D models — auto-fetch or bundled?**
   KiCad 3D model libraries are huge. Fetch on demand, bundle a subset, or rely on user configuration?

6. **How to test?**
   Golden-file tests on a set of reference boards: circuit → netlist → placed → routed → DRC-clean. Diff against known-good output on every change.

## 21. Rules Summary — One-Page Cheat Sheet

**Procedural primitives:** Part, Pin, Net, Bus, Circuit. Port from SKiDL.

**Connection operators:** `+=` (connect), `&` (series), `|` (parallel), `*` (duplicate). Port.

**Pin types:** 14 kinds; drive ordered NOCONNECT < NONE < PASSIVE < PULLUPDN < ONESIDE < TRISTATE < PUSHPULL < POWER. Port.

**Output:** netlist, KiCad PCB round-trip, Gerbers, STEP, BOM, pick-and-place CSV.
